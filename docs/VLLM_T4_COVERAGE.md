# vLLM 0.25.1 on Kaggle 2 × Tesla T4 — what Stokastisk exposes, what is verified, what is not

**This is not complete vLLM coverage and does not claim it.** Stokastisk bundles a T4-only vLLM 0.25.1 build (SM75, CUDA 13.0, `TRITON_ATTN`, no FlashAttention/FlashInfer/FlashMLA). Of vLLM's modules, a small path was **executed on Kaggle**; most of the rest is present in the wheel but **untested**, and some cannot work on SM75.
Detailed per-module tables are generated by `scripts/audit/vllm_inventory.py` (static analysis of the shipped wheel; re-runnable). Summary of the last run: 1967 modules classified.

| Class | Modules | Meaning |
|---|---|---|
| SUPPORTED | 19 | direct Kaggle execution evidence (Triton kernels compiled and launched on the T4s, the `LLM` entry, Qwen2, the Triton attention backend, the TP communicator, the sampler) |
| SUPPORTED_WITH_CONDITIONS | 537 | statically reachable from the executed entry points; the module itself is not individually proven executed |
| NEEDS_ADAPTATION | 10 | imports a module that was removed from the T4 wheel; only affects specific models/backends |
| NOT_SUPPORTED_SM75 | 183 | non-CUDA platforms, or SM80+/SM89+/SM90+/SM100+ features (name/gate heuristic) |
| EXCLUDED_FLASH_DEPENDENCY | 35 | FlashAttention / FlashInfer / FlashMLA modules, removed or inert |
| UNKNOWN_REQUIRES_EVIDENCE | 1183 | present, never run, not reachable from the executed path (includes 50+ model families and the OpenAI server stack) |
| NOT_IMPLEMENTED | 0 modules | at SDK level: L4/SM89 |

## Evidence tiers
`kaggle` = executed by the owner on 2 × T4 · `kaggle-kernel` = Triton kernel compiled and launched, output not asserted · `cpu-tests` = unit tests with mocks · `static` = source inspection only · `implemented-not-executed` = SDK code written but never run.

## Checking before you start (static, no GPU, no network)
```python
import stokastisk

print(stokastisk.feature_matrix()["bfloat16"])                      # NOT_SUPPORTED_SM75
stokastisk.check_dtype("half")                                       # ok; "bfloat16" raises StokastiskCompatibilityError
stokastisk.check_quantization("awq")                                 # allowed by capability, UNKNOWN_REQUIRES_EVIDENCE; "mxfp4" raises
report = stokastisk.check_model(architectures=["Qwen2ForCausalLM"])  # SUPPORTED (run on Kaggle); Qwen Omni raises (module removed from the T4 wheel)
print(report["status"])
```
`check_model` reads vLLM's model registry and import chain **without importing vLLM**. "Passes the static check" means the module and its unconditional imports exist; it does not mean the model loads or fits two T4s. Of 356 registered architectures, 346 pass and 10 are blocked (Qwen2.5/3 Omni, Qwen3-ASR, OpenPangu); only `Qwen2ForCausalLM` has Kaggle evidence.

## OpenAI-compatible server (implemented, **not executed**)
```python
import stokastisk
from stokastisk.serving import ServerProcess, stream_chat

config = stokastisk.StokastiskConfig(tensor_parallel_size=1)
with ServerProcess("Qwen/Qwen2.5-0.5B-Instruct", config, port=8000, log_path="/kaggle/working/server.log") as server:
    server.wait_ready(timeout=600)
    for piece in stream_chat(server.base_url, "Qwen/Qwen2.5-0.5B-Instruct", [{"role": "user", "content": "Name the capital of France."}]):
        print(piece, end="")
```
The server runs `vllm serve` in a child process with `--attention-backend TRITON_ATTN`, fp16 and the config's TP/PP; it needs `fastapi`, `uvicorn`, `starlette`, `openai`, `pydantic`, `prometheus_client`, `pyzmq`, `msgspec`, `cbor2`, `aiohttp`, which Stokastisk does not install (the Kaggle image is protected) — a missing package raises a clear error before launch. `replica_parallel` needs one server per GPU (`cuda_visible_devices="0"` / `"1"`). `/health`, `/metrics`, `/v1/models`, `/v1/chat/completions`, `/v1/completions` exist in the shipped source; none was called on Kaggle.

## Requires future Kaggle validation
Everything marked `implemented-not-executed` or `UNKNOWN_REQUIRES_EVIDENCE`: the OpenAI server and streaming, `LLM.chat`, structured outputs, prefix caching, chunked prefill, CUDA graphs, LoRA, multimodal (vision tower uses PyTorch SDPA on SM75, not Triton), embedding/pooling, speculative decoding, MLA models, quantization kernels, any model other than Qwen2.5-0.5B/1.5B. See `reports/` (local) for the module-level matrix.

## Unsupported on this build
bfloat16 · FlashAttention · FlashInfer · FlashMLA · FlashInfer all-reduce fusion · native FP8/FP4/MXFP4 kernels (SM89+/SM100) · DeepEP/NIXL/FlashInfer all2all · Qwen Omni models (module removed; restorable only with a new vLLM wheel) · L4/SM89 (`PLANNED_NOT_IMPLEMENTED`).
