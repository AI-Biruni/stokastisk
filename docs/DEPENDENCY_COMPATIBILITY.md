# Dependency compatibility — xgrammar / transformers (Stokastisk 0.1.0, vLLM 0.25.1)

## The finding
Kaggle's image has **transformers 5.20.2** (protected; vLLM 0.25.1 requires `>=5.5.3`). The pinned structured-output package `xgrammar==0.2.5.post1` declares in its wheel metadata
`Requires-Dist: transformers<5,>=4.38.0`. After the legacy installer ran, `pip check` therefore printed

    xgrammar 0.2.5.post1 has requirement transformers<5,>=4.38.0, but you have transformers 5.20.2.

(evidence: `evidence/kaggle-legacy-two-wheel/2026-11-12-notebook-13/prereq-install/02_install.json`, key `pip_check`). The legacy installer's own check only looked at lines beginning with `vllm`/`stokastisk`, so it printed
PASS although `pip check` was **not** clean. That was a defect of the check, not of the evidence file, and it is fixed in `scripts/kaggle/02_install_integrated.py` (before/after comparison; the one documented line is a WARNING, every other new line FAILS).

## Which xgrammar releases exist (PyPI metadata, queried 2026-11-12)
| xgrammar | Requires `transformers` | Requires `apache-tvm-ffi` | vLLM 0.25.1 pin `apache-tvm-ffi==0.1.9` |
|---|---|---|---|
| 0.2.5.post1 (**pinned, Kaggle-executed**) | `<5,>=4.38.0` | `>=0.1.9` | satisfied |
| 0.2.6, 0.2.7 | `>=4.38.0` (upper bound removed) | `>=0.1.10` | **violated** by 0.1.9 |
| 0.2.8, 0.2.9 | `>=4.38.0` | `>=0.1.11` | **violated** |

No release removes the `transformers<5` bound **and** accepts `apache-tvm-ffi==0.1.9`: moving to a clean xgrammar would trade the transformers conflict for a tvm-ffi conflict against vLLM's own declared pin, and would replace the only xgrammar build that has run on the T4s with one that has not. Both options leave `pip check` unclean; neither is silently adopted.

## What was verified (CPU, no vLLM, no GPU) — `scripts/audit/xgrammar_cpu_check.py`
xgrammar 0.2.5.post1 (+ tvm-ffi 0.1.9) **and** 0.2.6 (+ tvm-ffi 0.1.10), each installed with `pip --target` next to **transformers 5.22.2**: `TokenizerInfo.from_huggingface(Qwen2.5 tokenizer)`, `GrammarCompiler.compile_json_schema`,
`GrammarMatcher` accepting every token of a valid JSON document, rejecting an invalid first token, and `apply_token_bitmask_inplace` masking >99.99 % of the vocabulary — all pass for both. The only transformers symbols xgrammar imports are
`PreTrainedTokenizerBase` and `PreTrainedTokenizerFast` (`xgrammar/tokenizer_info.py`), which exist in transformers 5.x. Hence the `<5` bound is a stale metadata bound, not a functional incompatibility, for the code paths vLLM uses.
**Not verified:** GPU structured decoding through vLLM on the T4 (notebook 15's `engine` stage runs it: JSON-schema constrained generation with the bundled xgrammar backend), and the xgrammar Triton/CUDA bitmask kernels on SM75.

## Decision
Keep `xgrammar==0.2.5.post1` and `apache-tvm-ffi==0.1.9` (the exact pins executed on Kaggle in notebooks 01–14). Do not edit xgrammar's installed metadata. Report the conflict honestly everywhere: installer WARNING, notebook 15 WARNING, this page.
If notebook 15's structured-output check fails on the T4, this decision must be reopened (candidate: xgrammar 0.2.6 with `apache-tvm-ffi==0.1.10`, changing the integrated wheel's own metadata pin and re-verifying).

## Protected packages
The installer never resolves dependencies. The integrated wheel is installed with `--no-deps --no-index`; the eight missing pins (`requirements/kaggle-t4-core.txt`) are downloaded with `pip download --no-deps --require-hashes` using the sha256 of every published file (`requirements/kaggle-t4-core.hashes.txt`, generated by `scripts/release/gen_pin_hashes.py`) and installed `--no-deps --no-index`.
After installation every preinstalled distribution (torch 2.11.0+cu130, triton 3.6.0, nvidia-*, NCCL, transformers …) must be unchanged or the installer FAILS.
