## What build 4 changes (and what it does not)
Build 4 corrects the compatibility **reporting** shipped in the SDK: `stokastisk.compat` now records the Kaggle evidence that existed (OpenAI server, streaming, metrics, structured output, chat and generation) and `check_model()` answers per exact model id (`MODEL_EVIDENCE`) instead of per architecture; the `stokastisk.serving` docstring no longer says server verification is pending. Everything that executes inference is untouched: of 2,582 wheel members, 2,577 are byte-identical to build 3 — all 2,517 `vllm/**` files, all 6 native binaries, every dependency pin. The five that differ are `stokastisk/compat.py`, `stokastisk/serving.py` (docstring only, identical AST) and `METADATA`, `WHEEL`, `RECORD`. Report: `scripts/audit/wheel_delta.py` (summary in [docs/PRODUCTION_READINESS.md](docs/PRODUCTION_READINESS.md)).

## Known facts
TP=2, PP=2 and replicas are **slower** than TP=1 for a model that fits one T4 (PCIe host bridge, no NVLink). Kaggle resolves NCCL to its cu12 build 2.32.3; our binaries do not link it. Unsupported: bfloat16, Flash*, FP8/FP4, L4/SM89, Mistral-family models, OpenTelemetry exporters, direct `vllm.LLM`/`vllm serve`. Limits: [docs/PRODUCTION_READINESS.md](docs/PRODUCTION_READINESS.md).
